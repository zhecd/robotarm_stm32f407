# 数据流与状态含义

## 命令到运动

UART1 DMA 字节 → UART BSP 可用数据检查 → 纯 C 行组帧器 → G-code 语法结构 → AppSerial 会话 → Command 路径点 FIFO → Planner 全路径校验 → 按预算生成 MotionFrame → Motion 帧队列 → STEP ISR → 关节设备 → STEP/DIR 驱动。

AppSerial 每轮处理至多一条输入，Command/Planner 分次推进工作。规划器每次最多校验 16 段或生成 4 帧；帧队列满时返回主循环，持续无法提交达到 PLANNER_QUEUE_TIMEOUT_MS 后锁存故障。零步帧保留低速端点时长。

`ok` 表示当前路径通过校验并被接受；`queued` 表示进入 16 个可用槽的坐标 FIFO，尚未轮到完整路径校验。`M400` 还需等待规划、路径点 FIFO、STEP 执行与闭环恢复轨迹均空闲。它不测量末端是否在物理上精确到位。

## 反馈到状态

AS5600 单圈原始角 → 圆周均值 → 连续采样软件解圈 → 电机轴角度 → 根据 Home Pose、减速比与方向换算关节角 → StateService 快照。闭环使用电机轴角误差；软限位比较换算后的关节角。

StateService 的有效标志与失败次数必须和角度一起读取。M114 的 PLAN 是已规划参考，J/ENC 是反馈快照；诊断模式的 RAWENC 尚未建立回零后的关节参考。

## 停止与恢复

正常上电：通信/设备初始化并禁用输出 → CHECKING（先确认三个驱动配置，再检查同轮三轴反馈）→ 首次夹爪初始化 → HOMING（寻限位和退回）→ 编码器标定 → READY。任一轴暂不可读时按100ms间隔继续检查，10秒内未达到同轮三轴有效则FAILED；未回零时不把原始角度当成可信关节参考。驱动配置未确认则立即FAILED/FAULT:10，保持EN禁用，不初始化夹爪、不自动重试。M999从驱动配置确认重新开始，保留首故障直到本轮回零/标定成功；M112可以中止检查及回零。

限位、编码器异常、软限位、规划队列超时、补偿发散或 M112 → Motion 停止并清空帧 → App 将故障映射给 Safety → Command 取消路径点和 Planner 工作 → 拒绝新运动 → M999 重新回零/标定成功后恢复。

M112 是依赖串口和主循环响应的软件停止，不能替代硬件急停。回零阶段也处理停止与查询，其他运动请求被明确拒绝；READY 切换会丢弃尚未消费的输入。

## 共享数据

动作入口先调用 MotionService_IsActionAllowed，主动确认到期限位并检查 Safety、Motion 和 IRQ 状态；这也保护绕开 AppRuntime 的独立服务调用。READY 中先处理已有故障，再接收串口及判断 M400 完成，防止故障清空队列被解释为成功执行。

PS2 增量 → 单个短帧受理 → 更新规划位置和闭环理论目标 → STEP 执行；忙碌时拒绝下一段。松杆不再追加，已受理短帧继续完成；手柄数据无效则停止当前和未来帧、锁存 INPUT_LOST，使旧位置参考失效，重连不自动恢复。恢复须经过 M999 检查、回零与标定。

主循环生产帧，ISR 消费。发布完整帧和清除故障等操作采用短临界区；状态读取复制快照后退出临界区，再格式化通信内容。临界区内禁止 I2C、打印、轨迹计算和等待队列空间。电脑测试检查逻辑和调用边界，实际并发时序还需实机验证。
