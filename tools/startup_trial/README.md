## 固定动作合同

|阶段|M1|M2|M3|
|---|---|---|---|
|寻限位方向|D0|D0|D1|
|寻限位上限|200微步|200微步|200微步|
|退回方向|D1|D1|D0|
|原退回量|4000微步／100°关节角|1240微步／31°|200微步／5°|

每轮最多给每轴一个脉冲，最小间隔20000µs，即不超过50微步/秒。三轴并行寻限位，逐轴命中即停寻；全部命中才并行退回，短行程轴完成后保持不发STEP。共享EN会同时使能三路。最长退回约80秒，理想总时长不超过约84.02秒；通信、采样和标定会增加耗时，总硬截止90秒，不因延迟自动扩大。

真实正常初始化还会给MG90S发送一次原72°关闭目标、保持600毫秒。软件81修复App在HOMING期间漏调IdleStop导致保持拖长的问题。主循环推进到期停止；独立保护在PWM仍开启达700毫秒时切断并判失败。串口快照不证明实际角度或夹持力。

## 保护和完成的含义

- `trial_logic.c`不含HAL，管理单次许可、350ms主机KEEP租约、250ms主循环心跳和90秒总截止，按无符号差值处理时钟回绕。迟到KEEP、M999或新START都不能恢复本次窗口。
- `guard.c`初始化先禁用EN、拉低三STEP和PA1。TIM5独立截止，IWDG处理主循环/中断失活后的复位；复位仍回WAIT。GPIO和逐轴STEP入口采用短临界区重新检查许可和实际计数上限。
- 异常向量在Core真实入口显式调用停机钩子。汇编弱别名不能依靠链接器wrap重定向；`audit_binary.py`核对最终ELF的向量、故障分支、SysTick、main和TIM5入口。该静态检查不能替代实际故障时序验收。
- 正常App提交READY时，先记录实际Safety的HOMED/ALLOWED边界；立即切断输出，抑制TIM6启动，不进入READY周期补偿。随后主动HOST_STOP撤销全局参考和许可，末态OUTPUT_LOCKED/HOMED0/ALLOWED0。`M123 READY_HOMED:1 READY_ALLOWED:1`只证明到过该提交边界，不能当作结束后可运动。
- 不执行任意G-code、模式切换、额外夹爪开合、回零重试或整机联动。原正常固件功能和115200上位机协议不变；本身份是独立试验协议。

## 查询与记录

`M115`必须精确匹配STARTUP1和固定参数。`M123`报告WAIT0/ACTIVE1/DONE2/FAILED3、首因、USED、READY边界、EN、逐轴寻程和退回脉冲计数；这些是软件发脉冲记录，不是测得的位移。

`M124`每100ms重新读取三轴电机侧角度，报告有效掩码、样本年龄、序号、限位输入和ZERO_EPOCH。它使用Device的当前编码器零偏，FRAME为MOTOR，不能当作关节角。成功标定会改变零偏：旧缓存标为epoch0，标定后新样本为epoch1，不能跨epoch把坐标跳变解释为机构瞬移。读取失败或一轮读取超过150ms，活动窗口立即停止。

保留只读M114/M119/M408/M409/M410和停止M112。回零期间M409的UNAVAILABLE属于正常App尚未发布关节帧，连续反馈用M124。LED1存活、LED2/3/4分别映射M1/2/3实时限位。

`execute_after_approval.ps1`默认在创建串口前拒绝；需要本次ExecuteAuthorized及独立记录目录。先核身份、五轮WAIT/三限位松开/反馈/正常检查状态，再用CreateNew保存不可覆盖claim，只发一次START。KEEP约70ms，状态、反馈和夹爪约100ms采集；固件90秒、主机90.5秒监督。任一失败仅对已核身份的固件发送M112，保存首因，关闭串口，不复位、不重试。

`-SelfTest`只运行纯合同测试，不构造串口。正式部署需先备份Flash、烧录锁定候选并独立回读/无动作检查，通过后再部署已审批的动作候选。每个烧录和动作阶段都保留独立证据目录及claim，不能删除旧claim重新执行。

## 讲解和测试顺序

先读纯逻辑与时限，再读真实`svc_homing.c`的并行寻限位/原退回，接着读App的夹爪结果处理及HOMING保持任务，最后看guard如何限制已有功能与主机如何监督。电脑测试替换设备、时间和串口端口，不模拟App成功。Debug/Release各146项、八种ARM构建、二进制向量检查及负对照已通过；未实测整机回零、机械精度、碰撞余量或异常截止时序。原M3频繁EXTI的电气/软件根因仍未确定，保留正常过载锁存保护。
